# Terrain profiles

A profile describes moving ten-metre windows of one recorded session. The telemetry library derives suspension figures, IMU readings, grade and matching signals from processed telemetry and original GPS fixes. The profile stores measurements only; it holds no roughness classes. Each window can hold a frame, a fork and a rear axle IMU reading: the raw 1–80 Hz level, three band levels, the speed-removed level and the clipped share. Speed removal scales a level to 7 m/s with the exponent 0.7 for the frame and 0.9 for the fork and the rear axle. A reading is clipped when more than 2% of its window samples are at full scale. `TerrainProfile.HasImu` is true when the ride recorded any IMU. Grade reports its own availability. `TerrainProfileCalculator.AlgorithmVersion` versions the calculator.

A failed sensor reads zero. When a suspension or IMU sensor reads zero in more than half of its measured moving windows, the calculator drops all its readings for the ride. An IMU level below one count counts as zero, because the band-pass filter leaves a small residue next to live samples. A dropped IMU yields no matching series, scale or distribution, and a dropped frame IMU also removes grade. The rear axle IMU produces no matching series. The profile lists the dropped sensors, and the terrain source note names them.

The measurement summary holds the moving and climb distances and four level distributions: the speed-removed levels of the frame, fork and rear axle IMUs on descent windows and the raw frame level on climb windows. A distribution adds 10 m per eligible window to the `TerrainLevels.Bin` of its level. An eligible reading is moving, not silent, above zero and not clipped. `LevelDistribution` has value equality over its bins.

## Materialization

`TerrainProfileCoordinator` owns the device-local profile and the ride class summary. At startup and after session or track publications, one background evaluation gives the pending profiles, the scale of each setup and the pending class work. The coordinator runs one item at a time.

Profile work processes one recording at a time, newest first. An editor can prioritize a queued recording. A changed input supersedes the run. After a written commit, the coordinator publishes the committed key, outcome and summary onto the current session snapshot and clears its class key and class summary. If the inputs changed meanwhile, the status query reports `Pending` for that snapshot. A publication failure is logged and the queue continues.

Class work starts only when no profile work is queued or running, because profiles change scales. It runs per setup, in order of the newest session of each setup. A class run holds the setup ID, its scale key and the pending sessions with their profile keys. It reads their stored profiles, classifies and summarizes them on the background runner, and writes all summaries in one transaction. The write updates a row only while it holds a computed profile with the profile key of the class key; a skipped row stays `Pending` until the next evaluation. The written sessions publish in one step. A new evaluation that gives the setup another scale key supersedes the run, and a superseded run writes nothing. A read or write failure is logged once. Shutdown cancels and drains planning and both kinds of work.

The content token identifies the processed telemetry revision, selected full track and points revision, aligned recording window and track projection version. `TerrainProfileKey` adds the algorithm version. `TerrainClassKey` holds the profile key, the scale key and `TerrainClassifier.Version`. The exact reader and the SQLite write transaction use the same token rule as the status query. A computed row contains a summary and MessagePack profile, and later a class key and class summary. A terminal outcome contains only its key and reason.

## Availability

`SessionTerrainStatusQuery` derives the list and editor status from the session snapshot and track catalog. A session without processed telemetry is unavailable. A new key is pending. With matching inputs, the status exposes the current summary or the stored outcome. A recording with no selected track reaches `NoTrack` without a telemetry read. Missing original track fixes yield `ContentMissing`. A stale or missing telemetry read means the run is superseded, so it writes nothing.

A calculation failure is recorded for its input key. If the database write itself fails, the coordinator logs it once and publishes `Failed` for that key without a stored row. The next publication of the session from the database, or the next app start, runs it again. Authored metadata and sync clocks are independent of profile materialization.

`TerrainStatus.Current` describes the profile only. `SessionTerrainStatusQuery.EvaluateClasses` gives the `TerrainClassState` of a session: `Classified` when the profile is current, the setup scale has a ready bin and the stored class key matches; `Pending` when the stored class key is missing or different; `Unavailable` otherwise, including a session without a setup. The domain snapshot and the session summary carry the class state. The session row shows the rough share only for `Classified` with at least 300 m of classified distance.

## Classes

Classes are per setup. `SetupTerrainScaleQuery.Evaluate` derives a `SetupTerrainScale` for each setup from the current measurement summaries of its sessions; it is never stored. For each sensor it merges the distributions of the contributing rides. The median bin is the first bin where the cumulative distance reaches half of the total. A sensor is `Ready` with 3 contributing rides and 5,000 m, otherwise `NotEnoughData` with its rides and metres. `TerrainScaleKey` holds the ready median bins; `TerrainScaleKey.None` has none. A new ride that leaves every median in its bin leaves the key unchanged. `SetupTerrainScaleQuery.Catalog` gives the scale key of each setup from the session summaries.

`TerrainLevels` holds the level arithmetic. Twenty bins span one class step of 1.5×. The centre of Medium is the median of the bin. A reading's class value is its level in class steps from the median, plus 0.5. Below −1 is Smooth, below 0 Calm, below 1 Medium, below 2 Rough, otherwise Very rough.

`TerrainClassifier.Classify(profile, scale)` returns a `ClassifiedProfile` with one `ClassifiedWindow` per profile window. A reading is usable when its sensor has a ready median and its level is above zero. A descent window takes the mean value of its unclipped fork and rear axle readings; without one, the frame value; without a frame reading, the mean of the clipped fork and rear axle readings. The window records its `GroundSensors` source and class value. A climb window with a ready climb median and a frame reading is Smooth climb below the climb median and Technical climb at or above it; it has no class value or source. Single-window outliers merge last; the merge keeps the class value. Without a ready bin no window has a class. `TerrainClassifier.Summarize` gives the classified descent distance and its Rough and Very rough share. Every reader of a window class takes a `ClassifiedProfile`.

## Recorded editor

The editor loads on each change of the pair of profile status and setup scale key; a domain snapshot without a scale gives `TerrainScaleKey.None`. It reads the exact profile, classifies it on that scale and derives timed runs for both axes, segmented sensor, grade and pedal bob signals, and the distance share of each class source, on its background runner. The reducer accepts a loaded result only for the current pair. A change of status immediately removes the previous plot and map data. A change of only the scale key keeps the loaded terrain and the chosen scope until the new result replaces it; a result with the same profile key keeps the baseline. Without classes, a preset scope admits every window of its preset.

The strip title names the class source with the largest share of the classified descent windows, or none without classes. The tooltip lists the source shares, a clipped fork or rear axle reading left out of a class value, absent frame, fork or rear axle data in classified descent windows, each sensor whose setup scale is not ready yet with its rides and metres, and the ignored sensors. The roughness plot draws the frame, fork and rear axle levels; the guides of a curve are the class edges of its ready median bin. The grade trace uses the same five-window baseline as the grade bands.

## Analysis selection

The analysis scope is a preset narrowed by legend classes. Descents admits every non-climb window, including windows without grade. Climbs admits the two climb bands, and All admits every window. A legend class outside the preset cannot be selected, and an empty axis admits every class on that axis. Every preset uses moving windows only, so stopped time never enters the analysis. `TerrainSelectionQuery` intersects matching windows with the analysis range, joins adjacent intervals, and excludes intervals shorter than the minimum analysis duration. A partial window contributes its mean speed times the covered duration. Legend distances describe the corresponding class inside the analysis range. The result also reports the stopped time inside the range.

The editor keeps one scope choice per tab: the default, a chosen terrain scope or a segment comparison. The default is derived from the loaded profile: Descents when the profile has grade, otherwise All. No observer writes a scope when a profile arrives. A choice equal to the profile's default is stored as the default. The reducer evaluates the selection again only when the profile, the effective scope or the analysis range changes. With a loaded profile, the effective time selection is the scoped selection; without one, it is the analysis range. A segment comparison uses the analysis range. Analysis results are keyed on that selection, not on the scope, so statistics and Insights share one value. Plot overlays mark the selection of a chosen scope only.

## Bike response baseline

The baseline identity is the ordered set of current profile keys of other rides on the same bike. The editor observes summary commits throughout the tab lifetime and selects the identity synchronously on each commit. A changed identity invalidates the previous model. Exact profile reads, log-linear least-squares fitting and response measurements run on the background runner. A superseded fit cannot publish. A baseline read error is local to the response panel.

Climbing windows stay out of the fit and out of every response row, because pedalling and rider load drive the response there. Each target needs five compatible rides, 1,000 moving windows with positive observations, and independent variation in the log band levels and speed. Each target has predictor sets in order of preference: fork targets `Fork`, then `Frame`; shock targets `RearAxle`, then `Frame`; `PassedToFrame` `ForkAndRearAxle`, `Fork`, then `RearAxle`. A set is a candidate when the evaluated ride and, in a comparison, the paired ride have every sensor of the set; `PassedToFrame` also needs the frame IMU. The first candidate whose fit is `Fitted` wins; a set with too little data passes to the next. Each model carries its `GroundSensors` predictors, coverage and availability.

Insights measures the whole ride and each descent level inside the analysis time range, independently of the scope. Its analysis key includes the scale key, so a scale change recomputes it. `TerrainResponse.Describe` also accepts a window filter, so a caller can limit every row to the windows of a scope. Boundary-window distance and log residuals are weighted by the covered fraction. Ratios use the geometric mean of observed over predicted response. A row reports ratios from 150 m, and the presentation marks distances under 300 m as low confidence. Classification uses the bike-baseline repeat thresholds of 30% for suspension response and 10% for vibration passed to the frame. `TerrainResponse.Findings` lists every cell outside its repeat range as a typed finding: target, group, signed deviation and confidence. The confidence is low under 300 m. The app turns findings into verdicts and rows into a deviation chart in `Terrain/Formatting/TerrainResponseReports`; views build no sentences.

## Comfort

`TerrainComfort` describes, per descent class of the classified profile, the moving ground inside a range that a window filter admits. Each row gives the distance, the fork and shock activity (RMS velocity, mm/s) and the frame level (band-limited vibration, g). The figures are as measured, so faster riding raises them. Each figure is the quadratic mean of its windows, weighted by covered time, because the window figures are RMS values. A missing sensor leaves its figure empty.

## Climbing

`TerrainClimbing` describes the moving climb windows inside the analysis range, with covered fractions. It reports distance, time, the net height gained from the window grades, the time with detected pedalling, and the split into smooth and technical climb levels. Bob and cadence are time-weighted medians over the pedalled climb windows only, because travel at the pedal frequency on rough climbs is ground input. Mean travel per end compares climb windows with the descent bands; flat ground stays out. Below 120 s of pedalled climbing there is no summary.

## Character (experimental)

`TerrainCharacter` reports, per end, the moving descent ground of class Medium or rougher inside the analysis range that has a median compression stroke size. It splits that distance into big hits and chatter by the stroke size as a share of the end's max travel: rear big hits from 16% and chatter below 8%, front big hits from 20% and chatter below 9%. These are one bike's quartiles on rough ground and stay provisional. A share is dominant when it covers more than half of at least 300 m. The Bike response page shows the dominant shares as an experimental hint in the response card. A ride without classes shows no hint.

## Same-trail comparison

Ground alignment refines the GPS time map with a shared frame IMU, or a shared fork IMU when frame data is absent. `TerrainRunAlignment` cuts the source range into 150 m chunks every 75 m. A chunk is a candidate when both runs have matching values for 80% of its metres. Each candidate searches 40 m to either side and is accepted when its best correlation is at least 0.6 below the search limit. An accepted chunk is dropped when its shift differs by more than 5 m (`NeighbourShiftToleranceMetres`) from every neighbouring accepted chunk. The pair aligns only when at least half of the candidates are accepted (`MinimumAcceptedShare`, counted before the drop) and two chunks remain. Unrelated ground correlates by chance in a few chunks, so the share rule, not the chunk count, rejects it. Only moving windows within 75 m of a remaining centre enter the comparison, at the shift interpolated between remaining centres.

Each run is classified on the scale of its own setup, taken from the scale catalogue. A matched pair's class is `TerrainLevels.Classify` of the mean of the two class values; a pair with a run without a class value has no class. The pair fit excludes both compared rides and requires compatible predictor scales. Rows cover all matched windows and each class. A row reports pace and ratios from 150 m, with the same low-confidence mark under 300 m. Pace reports the median and interquartile range. Suspension response and vibration passed to the frame compare each ride’s log residual on jointly measured windows. The same-position RMS ratios use the observed speed ratio to the power 0.9 and remain available without a baseline. Repeat limits are 20% for RMS, compression and same-position response, 25% for rebound and 5% for vibration passed to the frame. `TerrainRunComparison.Findings` returns the same typed findings for the response ratios.

## Known-trail average

Each source window receives at most one measurement from each aligned run. Each run is classified on the scale of its own setup. Measured frame, fork and rear axle levels use geometric means of the speed-removed levels of at least three readings. Grade uses an arithmetic mean and the same contiguous 50 m baseline as a single ride. A stopped source window stays in the average without values or classes, so the baseline reaches past it.

A descent window's class is `TerrainLevels.Classify` of the mean class value of at least three runs with a class value. A climb window takes the majority climb class of at least three runs with a climb class; a tie gives Technical climb. Averaged bands and classes merge single-window outliers as a single ride does. A comparison using the average keeps windows without an averaged class in its all-terrain row only. A change of the source profile key, the source scale key or the scale catalogue starts a new average. Average values live for the current Match in the recorded editor.
