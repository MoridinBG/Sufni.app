# Theming

> Part of the [Sufni.App architecture documentation](../ARCHITECTURE.md). This file covers the app theme model, Avalonia resource bridge, runtime theme service, and theme ownership boundaries. Presentation layering and dependency rules live in [UI Architecture](ui.md).

Two `SufniTheme` instances make up the theme model: `SufniDarkTheme` and `SufniLightTheme`. The pure theme model lives under `Sufni.App/Sufni.App/Infrastructure/Theming/` (namespace `Sufni.App.Infrastructure.Theming`), next to the runtime theme service, the resource bridge and dictionary, and `SufniColorExtensions`. It contains the two themes, their `SufniDarkPalette`/`SufniLightPalette` primitives, `SufniThemeMode`, the `SufniThemes` resolver, and the `Avalonia.Color.WithAlpha(double)` helper (`SufniColorAlphaExtensions`).

- **Snapshot.** Each theme is a record-shaped snapshot of every color and dimension, grouped by role: surfaces, text, lines, actions, status, selection, tabs, nav rail, lists, search bars, map overlays, splitters, fields, drag/drop, recorded signal rows, plots, series, typography, and spacing. The model names the semantic role first.
- **Colors.** Color tokens use `Avalonia.Media.Color`. ScottPlot code converts them through `SufniColorExtensions.ToScottPlotColor()`.
- **Palettes.** Raw hex literals belong only in `SufniDarkPalette` and `SufniLightPalette`. They define descriptive named colors (e.g. `Obsidian`, `SlateAbyss`, `AccentBlue` for dark; `Cloud`, `Linen`, `AccentBlue` for light; depth-ramp families like `Tar*`/`Pitch*`/`Void*` and `Sand*`/`Clay*`/`Earth*`). A name that appears in both palettes (e.g. `AccentBlue`, `DangerRed`, `MarkerBlue`) must resolve to the same hex on both sides.
- **Builder.** `SufniThemeBuilder.Build(SufniThemeInputs)` owns the shared composition: cross-referenced tokens (e.g. `Tab.Text` from `Text.Secondary`), fixed opacities and dimensions, marker alphas, and the final assembly. It derives the plot depth backgrounds from the signal-row depth themes.
- **Inputs.** `SufniThemeInputs` holds the values that differ between dark and light. Each theme file builds its `Surface`/`Text`/`Line` bundles from its palette (`using static`), supplies the divergent leaves (depth ramps, map-overlay surface, plot grid/axis/cursor/preview/reference colors, etc.), and delegates the rest. A new divergent token is a compile error until both themes supply it.
- **Consumers.** Views and plot classes consume only role tokens, never primitives or hex.
- **Series.** Series and travel-zone colors are identical in both themes. They encode signal meaning (front/rear/IMU sources) and must not depth-shift.
- **Map overlay.** The map overlay panel follows the active theme (`Surface.Input` in dark, `Surface.Elevated` in light), so the chrome around the Mapsui map matches the UI. Its 0.9 opacity keeps both palettes legible over the tile imagery.

`SufniThemeResourceBridge` splits its keys into two populators. `PopulateRoot(...)` writes variant-invariant tokens (spacing, typography, dimensions, opacities, font sizes, and the FluentTheme overlay constants) to the root dictionary. `PopulateVariant(..., theme)` writes every color, brush, and FluentTheme resource override (`ButtonBackground`, `TextControlBackground*`, `ComboBox*`, `CalendarDatePicker*`, `ExpanderHeader*`, `FlyoutPresenter*`) into a per-variant child dictionary. `SufniThemeResourceDictionary` registers those child dictionaries under `ThemeDictionaries[ThemeVariant.Dark]` and `[ThemeVariant.Light]`, so Avalonia's variant resolution does the lookup. New XAML should prefer role resources such as `SufniFieldLabel`, `SufniTabIndicator`, `SufniMapOverlaySurface`, and `SufniPlotGridMajor`, and should use `DynamicResource` (not `StaticResource`) for any variant-sensitive key so the binding re-resolves when the variant flips.

`SufniThemes` is the theme resolver. It maps `SufniThemeMode` / `ThemeVariant` to `SufniDarkTheme` or `SufniLightTheme`, exposes `ToVariant(...)` for applying a mode to Avalonia (`System` maps to `ThemeVariant.Default`), and owns the variant-invariant tokens: telemetry colors through `SignalSeries` / `TravelZoneRamp`, and the dimension tokens through `Typography` / `Spacing`. Both `SufniDarkTheme` and `SufniLightTheme` reference these shared instances rather than redeclaring them, so they cannot drift apart and `SufniThemeResourceBridge.PopulateRoot` (which writes typography/spacing as variant-invariant root resources) stays correct by construction. Code that needs signal colors should use those invariant accessors instead of borrowing values from the dark theme.

`IThemeService` (`Infrastructure/Theming/IThemeService.cs`, implemented by `ThemeService`) owns the current `SufniThemeMode` (`Mode`). It exposes `EffectiveMode` for the active light/dark palette, a `Current` snapshot of that `SufniTheme`, and `IsSystemThemeAvailable`. It raises `ThemeChanged` and offers `ToggleAsync` / `SetAsync(mode)` / `InitializeAsync`.

- `System` mode is available only when Avalonia platform settings expose a concrete `PlatformThemeVariant.Light` or `.Dark`. Otherwise the service normalizes `System` to `Dark`, and the UI cycles only dark and light.
- `SetAsync` applies on the UI thread *first*: it sets `Application.Current.RequestedThemeVariant` and raises `ThemeChanged`. It then persists through `IThemePreferences.SetModeAsync`, so a failing apply does not corrupt the persisted choice.
- `App.Initialize()` applies the theme from `PlatformRoot.LaunchPreferences` before `AvaloniaXamlLoader.Load(this)`, which prevents a default-then-persisted flash. `AppPreferences.ReadLaunchValues` reads the document once in the head; runtime preferences start from the same snapshot.

Non-DI consumers do not use a mutable global current theme. Avalonia controls that own theme-derived state resolve `SufniThemes.FromVariant(ActualThemeVariant)` when attached and whenever `ThemeVariantScope.ActualThemeVariantProperty` changes. `SufniPlotView` exposes a `protected virtual void OnThemeChanged(SufniTheme)` hook that subclasses override to call `plot.ApplyTheme(theme)` and optionally `RequestReload()` so overlays baked at `LoadTelemetryData` time (airtime spans, marker lines, cursor tooltips) repaint with the new palette. The plot models accept an optional `SufniTheme` at construction; views pass their resolved current theme, while direct test/service construction falls back to `SufniThemes.Fallback`. `SignalRow`, `SignalRowsRoot`, and `SignalBaseRowDivider` use the same variant-resolution path for their drag-feedback, drop-target, connector, and divider brushes.

Selection and disabled visuals are separate contracts. Selection resources (`SufniSelection*`) identify the active or chosen item through subtle surfaces and indicators. Disabled resources (`SufniActionDisabled*`, `SufniTextDisabled`, and disabled field borders) describe unavailable actions or input. Avoid reusing disabled colors to mean selected state, hover state, or low priority text.

Recorded signal row depth styling is owned by the theme. `SignalRow` reads `SignalRow.ByDepth(...)` and `Plot.ByDepth(...)` so root, hosted level 1, hosted level 2, and hosted level 3+ rows can have different container, header, figure, and data-area defaults while keeping plot series colors stable. Drag feedback, drop targets, hierarchy connector lines, root drop zones, and base-row dividers also come from theme drag/drop and spacing tokens.

The desktop sidebar (`MainPagesDesktopView`) and the mobile menu drawer (`SidePanel`) both expose a theme-cycle button bound to `MainPagesViewModel.ToggleThemeCommand`. The displayed icon is chosen by `ObjectConverters.Equal` against `CurrentThemeMode`: sun for the selected light mode, moon for the selected dark mode, and a half-circle icon for the selected system mode. `MainPagesViewModel` mirrors `CurrentThemeMode`, `EffectiveThemeMode`, `NextThemeMode`, and `IsSystemThemeAvailable` from `IThemeService.ThemeChanged`. `NextThemeMode` gives the cycle destination; the icon shows the current mode. Theme mode persists through the device-local `IThemePreferences` facet and never travels through sync. `ThemeService` reads it at initialization and applies later mode changes through its own UI-dispatch boundary.

Map overlay theming stops at the app chrome around Mapsui. The status overlay in `MapView.axaml` uses `SufniMapOverlay*` resources for surface, opacity, padding, corner radius, and text. Map tiles, tracks, and geometry styling remain owned by the map/track rendering layer rather than by Avalonia control resources.
