SESSION CORE TEST AUDIT — 2026-11-03

Scope and result
333 actual test methods in 39 test source files, plus one assigned non-test driver (40 files total). Theory is one method, not one row. Exact file/method coverage reconciled against method-inventory.json. Verdicts: KEEP 161; REWRITE 117; MERGE 24; REMOVE 31; UNPROVEN 0. Existing retention earned by 48.3%; 172 methods do not earn retention in their current shape. A rewrite recommendation is not retention.

Static review only. Read test bodies and helpers, current architecture/manifest/testing context, relevant production implementations and public consumers. No production/test edits; no test execution, mutation run, coverage claim or empirical performance claim. TempDatabase/TempDirectory naturally allocate under system temp outside this project, so running those tests was deliberately avoided under the supplied restriction. CSV assertions are excerpts, not full proof transcripts; each behavior/problem explains the actual useful counterexample or why assertions miss it.

Public boundary rule
An internal implementation of a real public workflow/service interface can earn KEEP when a test exercises that interface's observable business outcome. Internal editor reducer, intent/effect, tree helper, metadata builder and internal-only cache-reader interfaces do not qualify merely because their methods are public. Publicly visible field copying also fails the bar. Identity, exact mock counts, or property enumerations are not value evidence by themselves. Preserved injected diagnostic details are distinct from asserting text generated by exceptions/user messages.

Architecture contradictions/drift encountered (report only)
- RecordedSessionProjection.FlushPendingRecomputes is async void (production line 247), starts background evaluation without a cancellation scope/task retained by IDisposable, and catches then rethrows evaluation failures (272-275). Dispose suppresses later publication but cannot cancel/drain that worker. This conflicts with manifest sections 12/13/16's explicit resource owner, draining and typed failure boundary. Current tests chiefly cover stale/removal rejection, not lifetime drainage/failure state; do not infer broader lifecycle correctness from those keeps. No code fix was made.
- During initial reading docs/architecture/ui-state.md had a broad caveat saying existing projection consumers had not migrated to StorePublication.Committed, although RecordedSessionProjection already did. A later recheck found that caveat removed by concurrent external documentation edits. This is resolved documentation drift, not an outstanding finding; this audit did not edit architecture docs.
- Architecture says metadata reuse preserves current derived fields; actual SessionRepository.PutSessionAsync matches that even for existing tombstones. Test-harness PutProcessedSessionAsync is a separate nontransactional fixture composition and must not be mistaken for the production import workflow described in docs.
