Standard and boundary interpretation
Read AGENTS.md, TESTING.md, VIEW-TESTING.md, ARCHITECTURE.md, ARCHITECTURE-MANIFEST.md and relevant UI/workflow architecture context; checked actual public consumers and implementation surfaces before classifying. A public member on an internal-only plotting helper does not become a public contract. Conversely public IAppStartup/IAppDataRefresher operations are meaningful application contracts even if instantiated through an internal concrete implementation. Those are judged on actual outcomes, not constructor accessibility. Assertions about generated property copying, framework collections, private/protected machinery or mock calls alone do not earn retention. Serialization literals and established historical document shapes can be genuine compatibility contracts.

Architecture observations and limits
No confirmed production architecture contradiction requiring a new scope was established in this slice. The strongest contradictions are test infrastructure mirroring domain/persistence policy and view tests asserting ownership beneath the public view boundary, against TESTING.md and manifest principles 5/10/20/22. A public interface is considered by semantics: directly targeting internal plotting helper buffers/algorithms still fails, while public startup/refresh lifetimes can earn KEEP. StorePublication batch suppresses store notifications until batch end but per-store CombineLatest may still emit intermediate pairs while notifications release; coherent joined consumers use Committed. The synthetic tuple test must not be misrepresented as proving all reactive subscribers see atomic cross-store changes.
