Live DAQ and Acquisition test retention audit — 2026-11-03

Scope and decision rule
Reviewed all 408 actual test-method bodies in the 50 assigned test-bearing files, the six assigned standalone support sources, relevant shared fixtures, public contracts and owning production paths. The initial scan's 410 attribute occurrences include two "[AvaloniaFact]" strings in exception messages, not tests. CSV uses exact declaration lines from method-inventory.json; each theory is one row. No production or test source was changed. No tests, builds or mutations were run; no external directories were accessed.

Totals: KEEP 211; REWRITE 157; MERGE 17; REMOVE 21; UNPROVEN 2. Total 408.
Only KEEP is retained as written. REWRITE preserves a valuable scenario, not the existing method. MERGE identifies a named survivor (sometimes itself requiring rewrite). REMOVE does not establish unique useful behavior. UNPROVEN is not retained.

Architecture context
Required context read: AGENTS.md, docs/TESTING.md, docs/VIEW-TESTING.md, docs/ARCHITECTURE.md, docs/ARCHITECTURE-MANIFEST.md, acquisition.md, daq-management.md, live-streaming.md, live-session.md, and relevant UI/workflow sections. Verified boundaries include IImportSessionsCoordinator/ITelemetryDataStore, IDaqManagementService/IDaqManagementSession, ILiveDaqSharedStream/registry, ILiveSessionService and store/query/editor consumers.

Internal implementation construction is not itself grounds for rejection when the method exercises a genuine public I* contract. Conversely, public C# visibility does not rescue plain helper state/identity inventories. Public documented wire codecs do have a compatibility contract: independent bytes and meaningful decoding/encoding can earn KEEP without adding expensive socket integration. Internal ManagementClient/ManagementProtocolReader and ILiveSignalPipeline helper-only tests need retargeting. No blanket rejection of loopback state/lifetime tests using frame fixtures was applied.

Strongest actionable findings
1. Vacuous reconciliation protection:
   Sufni.App.Tests/LiveDaq/Coordinators/LiveDaqCoordinatorTests.cs:210 Reconcile_PublishesAtomicUpdate_WithoutTransientEmptyState
   The only assertions iterate observedStates. If reconciliation emits nothing, the loop has zero assertions. Require at least one expected publication and expected identities/online transition before asserting absence of intermediate partial states.

2. The advertised stale-bake regression is not actually forced:
   Sufni.App.Tests/LiveDaq/ViewModels/Editors/LiveSessionDetailViewModelTests.cs:544 Bake_SecondSnapshot_CancelsInFlightTokenAndIgnoresStaleResult
   The first presentation provider blocks in firstBakeGate.Task.WaitAsync(capturedFirstToken). Canceling the token makes the provider cooperate by throwing before the old value can be applied. A missing consumer-side stale-result check can therefore survive. Use a deliberately noncooperative first completion, let second result win, then release old result and assert latest image still visible.

3. Fake-driven outcome echo:
   Sufni.App.Tests/LiveDaq/ViewModels/Editors/LiveSessionDetailViewModelTests.cs:348 SaveCommand_ResetsCaptureAndReportsWarning_WhenCommittedSavePublicationFails
   The SaveCaptureAsync substitute calls PublishSnapshot(Empty) before returning Saved. The assertion that Save is disabled does not establish editor-owned cleanup. Keep the useful warning/navigation projection in a focused method and assert editor-owned presentation cleanup through an independent service state/result sequence.
   Sufni.App.Tests/Acquisition/Coordinators/ImportSessionsCoordinatorTests.cs:481 ImportAsync_OverlapsDownloadWithProcessing
   Gates do demonstrate second download progresses while first processing is held. However both default/second sources contain identical [1,2,3] bytes and the default repository always returns Inserted; expecting two Imported results is inconsistent with real content-hash deduplication. Use distinct bytes/stateful repository while keeping deterministic progress gates.

4. Wire oracle coupling is real, but narrower than "all protocol tests are bad":
   ManagementProtocolTestFrames calls production ManagementProtocolReader.CreateFrame; ManagementRequestReader calls its ParseHeader. A changed MGMT magic/version/header layout can be accepted by both fake device and SUT.
   LiveProtocolTestFrames similarly uses production LiveV2ProtocolReader.CreateFrame (and ToV2StreamMask); LiveV2RequestReader calls production ParseHeader.
   Sufni.App.Tests/LiveDaq/Services/LiveStreaming/LiveDaqV2ClientTests.cs:68 StartPreviewAsync_ReturnsStarted_WhenAckAndSessionHeaderReceived
   Sufni.App.Tests/LiveDaq/Services/LiveStreaming/LiveDaqV3ClientTests.cs:35 ConnectAsync_SendsHandshakeBeforeAnyFrame
   Sufni.App.Tests/Acquisition/Services/Management/DaqManagementServiceTests.cs:315 WriteConfigAsync_SendsChunkedUpload_AndReturnsCommitResult
   These methods claim outgoing/start wire correctness partly through the same production encoder/decoder or exact initial request-ID seed. Replace the header oracle with literal captured/frozen bytes or independent fixed-offset decoding, and test correlation relative to observed ID rather than incidental seed.
   Useful payload, error and lifecycle behavior can still be retained when independently asserted; that is why many client/service state tests remain KEEP.

Assigned standalone support assessment (all six, no invented test rows)
A. Sufni.App.Tests/Acquisition/Services/Management/ManagementProtocolTestFrames.cs
   Payload offsets are handwritten and reusable, but envelopes use production CreateFrame and payload sizes/type codes use production constants. Keep mechanics only after independent frozen MGMT envelope baseline is added; do not call this an independent end-to-end protocol oracle.

B. Sufni.App.Tests/Acquisition/Services/Management/ManagementRequestFrames.cs
   Small test-only request records make fake-device scripts legible. No standalone behavior needs tests. Keep only types consumed by retained service/codec scenarios; avoid production schema/record inventories.

C. Sufni.App.Tests/Acquisition/Services/Management/ManagementRequestReader.cs
   Uses production FramedMessageReader and ManagementProtocolReader.ParseHeader. This is a correlated request oracle, not independent decoding. Replace only header interpretation for ABI tests with small literal fixed-offset reader; share payload decoding mechanically. Do not build a second generic production parser.

D. Sufni.App.Tests/Acquisition/Services/Management/ManagementTestServer.cs
   Useful small loopback socket owner. Accept/Read operations and server tasks lack consistent runner cancellation/bounded cleanup. Reuse a small shared protocol I/O fixture rather than repeat listener lifecycle. Do not make its accept/read/call counts tests.

E. Sufni.App.Tests/LiveDaq/Services/LiveStreaming/LiveProtocolTestFrames.cs
   Useful canonical model inputs and handwritten v2 payloads. Envelope CreateFrame and stream-mask conversion call production helpers, so magic/version/header and mask ABI can drift in lockstep. Preserve canonical model builders; separate frozen v2 wire vectors from dynamic scenario construction.

F. Sufni.App.Tests/LiveDaq/Services/LiveStreaming/LiveV3ProtocolTestFrames.cs
   This independently writes its compact envelope and payload offsets with BinaryWriter/BinaryPrimitives; that is stronger than v2/MGMT reusing production encoder. Shared constants alone are not the same defect. Its SessionHeader aggregate mask also calls production SstV5ProtocolConstants.StreamMaskForKind: pin that numeric mapping independently when asserting ABI stability. Keep focused reusable fixtures; avoid expanding the 787-line generator to mirror every implementation field.

Duplicated support and concrete small reuse targets

Consolidate into TestSupport/Io/ProtocolStreamIo.ReadExactAsync with cancellation and bounded owner lifetime; generic client type is unnecessary for byte I/O.

- Repeated live session contexts and StubLiveSessionService setup appear in compact/desktop view tests and VM tests. Prefer a small TestSupport/LiveDaq/TestLiveDaqContexts immutable builder plus existing StubLiveSessionService. Avoid combining coordinator, transport, repository, view and clock into one giant harness.
- Mounted window close/dispatcher-drain wrappers repeat across live/import view files. Remove wrappers along with inventory-only tests first; for retained mounted scenarios use existing ViewTestHelpers.ShowViewAsync and one small typed disposable host if needed.
- ImportWorkflowHarness defaults all sources to the same [1,2,3] and repository always returns Inserted. Useful for isolated routing, dangerous for multiple-import/dedup claims. Tests needing durable facts should use InMemorySessionRepository and explicit distinct source bytes; do not silently make the global harness emulate all repository policy.
- LiveSessionServiceTests.BlockingOnceBackgroundTaskRunner duplicates first-work gate mechanics available in async test support. Reuse a narrow gate/deferred runner if its behavior fits. Keep scenario-specific frame sequences in tests.
- AssertEventuallyAsync in shared-stream tests uses real-time polling with its own timeout token; prefer observable completion gates for state transitions where available.

Architecture contradictions and limits
No new production architecture violation was established strongly enough here to recommend an out-of-scope fix. The direct internal tests, exact buffer/revision/cache-identity constraints and mock call sequencing conflict with docs/TESTING.md and manifest section 20's facts/outcomes standard; those are test recommendations, not authorization to change production.
The documented in-memory live capture lifetime and separation of display loss from saved facts were honored in retention decisions. Query caching is permitted for expensive derivation, but reference identity alone is not its public contract.

Limitations
This is static source review, not a passing-suite report or empirical mutation proof. Counterexamples above describe changes the asserted public behavior should reject, not mutations executed. Native platforms/devices, real firmware capture provenance and runtime timing were not exercised. KEEP can still have maintenance opportunities; it specifically means the existing method asserts a useful distinct contract, not that it proves all behavior implied by its name. Shared wire fixtures leave known ABI blind spots identified above. No test or production changes were made.
